06 / Research / in development

Mnemra

Memory starts with who can access it.

An agent memory layer exploring typed shards, provenance, and access checks before relevance ranking.

FastAPI · React · OpenRouter
Read the build story ↗

The problem

An agent remembering something does not mean it should be allowed to use it everywhere. Retrieval alone does not settle access boundaries.

My contribution

Co-building a memory architecture with typed shards, provenance, cascade deletion, and a two-lane write gate.

A decision that matters

Apply access checks before relevance ranking. The intended evaluation compares leak rate, format violations, and token cost; results are not yet presented here.

Evidence & status

Research project in development. The architecture and evaluation plan are being developed together.

05 / Ways to work together

What can we build?

Bring the problem, even if the brief isn’t clear yet. We can work out what is worth automating, build a useful first version, and take it into production.

AI products & assistants

Build a useful AI feature around your users’ actual workflow: retrieval, model integration, memory, APIs, and the interface around it. Start with one clear use case and define how to check it works.

Workflow automation

Connect the tools your team already uses. Reduce repeated data entry, build operational dashboards, and make the handoff clear enough for people to keep using it.

Applied machine learning

Forecasting, ranking, segmentation, and prediction. Start with the business question, build a baseline, validate carefully, and serve predictions through an API.
